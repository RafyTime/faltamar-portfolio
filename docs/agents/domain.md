# Domain docs

This repo uses a single root glossary and architecture decision records.

Before exploring the codebase, read root `GLOSSARY.md` if present
and relevant ADRs in `docs/adr/`. Proceed silently when these
files are absent. Create them when domain terms or decisions
are resolved through the domain-modeling workflow.

Use `GLOSSARY.md` wherever an engineering skill requests
`CONTEXT.md`. This repo convention overrides those older paths.

Use the glossary's terms in tickets, proposals, and code discussions.
When a needed term is missing, record the gap for domain modeling.
If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
